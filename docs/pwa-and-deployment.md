# iPhone、PWA 與部署操作

整理日期：2026/11/09（台灣）。本次階段 4 已準備程式及自動化驗證，尚未發布新版。先前測試站仍使用舊版，以下新功能需核准發布後才能在該網址測試。

## 在 iPhone 開啟

1. 新版發布後，以 **Safari** 開啟 `https://joyce097054-cloud.github.io/sendai-trip-planner/`。不用在手機輸入指令。
2. 保持連線，滑到頁尾點「加入主畫面與離線使用」。看到「離線內容已準備完成」才代表這個模式的靜態內容下載成功。
3. 點 Safari「分享」→「加入主畫面」，確認名稱「仙台手帳」並加入。不同 iOS 的分享位置可能不同。
4. 從新圖示開啟，確認說明中顯示「目前以主畫面模式開啟」，再確認一次離線內容狀態。
5. 若分帳沒有帶入原帳本，在分帳頁貼上原本的**完整私人旅程連結**。不用重新註冊、收信或另建帳本。兩位帳務參與者的名字不隨裝置改變。

Safari、聊天 App 內建瀏覽器及主畫面 App 的儲存空間可能不同。個人行程、清單、照片要從原模式匯出完整 JSON，再到新模式匯入；匯入會經確認後取代目標模式的本機內容。不要為了更新而清除網站資料。雲端分帳透過私人連結取回，JSON 不包含共同帳務；帳務可另外匯出 CSV。

## 離線與更新

下載內容只有專案靜態檔案：首頁、程式、樣式、圖示、插畫與四張使用者提供的教學原圖。Service Worker 僅控制 App 的部署子路徑；Supabase／Auth／Realtime、天氣 API、未知網址與含查詢參數的資源不存入 Cache Storage。私人連結片段不放進 manifest 或快取鍵。

- 首次下載完成後，離線仍可重新開啟、切換行程／指南、編輯個人行程與清單、讀取本機照片及原圖。照片仍存 IndexedDB，不存入靜態快取。
- 天氣與共同帳務需網路；分帳離線禁止送出，不建立離線佇列。恢復連線會重新抓取最新帳務，不以整份本機帳本覆蓋雲端。
- 新版先完整下載，再顯示「更新並重新載入」。請先儲存正在編輯的表單；確認後才重新載入。其他分頁的版本啟用不會強制重載此頁。
- 新版下載失敗時保留舊版。更新保留最近兩版此 App 靜態快取，不清除其他 App 快取、localStorage 或 IndexedDB。
- 頁尾可「檢查更新」。若瀏覽器回收了靜態檔案，保持連線，在說明中點「重新準備離線內容」。這不會刪除旅記或照片。
- 系統仍可能回收瀏覽器儲存空間；PWA 安裝與靜態快取都不是備份。請定期將 JSON 存到自己保管的檔案，並保留私人連結與帳務 CSV。

本機開發模式不註冊 Service Worker；`npm run preview` 的 localhost 與正式 HTTPS 產物可啟用。電腦單檔版內嵌資源，明確停用 Service Worker 與 manifest，避免與網路版混淆。

## 開發者：準備與發布

沿用 GitHub Pages 和現有 Supabase，無須 Vercel 帳號；本階段不新增資料表、不重跑 001／002 SQL、不更改匿名驗證或 RLS。既有設定見 [Supabase 指南](supabase-setup.md)。

1. 確認原裝置已有 JSON 備份與帳務 CSV，私人連結自行安全保管。
2. 使用 Node.js 22.12 以上，檢出已審核的提交；執行 `npm ci`。`.env.local` 放現有 `VITE_SUPABASE_URL`（HTTPS 專案根網址，無 `/rest/v1/`）及 `VITE_SUPABASE_PUBLISHABLE_KEY`。不要放 Secret、service role 或資料庫密碼。
3. 執行 TypeScript、建置及相關測試；再執行 `npm run prepare:pages`。這只建立 `dist/`，不推送分支、不更新網站。
4. 確認 `dist/deployment.json` 的 `sourceCommit` 是欲發布提交、`sourceDirty` 為 `false`、`ledgerClientConfigured` 為 `true`，並與 `dist/pwa-build.json` 比對 `pwaVersion`。這只驗證本機公開設定及產物，不能代替正式 Supabase 連線測試。
5. **取得使用者對具體版本的發布同意後**，執行 `npm run deploy:pages -- --publish`。沒有明確旗標、工作目錄未提交或公開設定缺失時會停止；Vite 也會拒絕將私人金鑰打包。
6. 腳本只在獨立 `gh-pages` 建立發布提交，保留父提交、不強推、不更改 `main`，並檢查既有發布的 App 標記。一般功能分支 push 不會更新網站。
7. 首次才需 GitHub **Settings → Pages → Deploy from a branch → gh-pages → /(root) → Save**。既有站點保持原設定；不要為了部署自行改變儲存庫可見性。確認 HTTPS 可用。
8. Pages 發布完成後，以網路直接開啟 `/sendai-trip-planner/deployment.json` 比對提交與 PWA 版本；此 JSON 不由 Service Worker 快取。推送成功不等於站點已更新。再確認首頁、manifest、圖示與四張圖無 404，舊裝置收到手動更新提示。
9. 執行下方兩種真實 iPhone 模式與兩裝置驗收，記錄版本、iOS、日期和實際結果。未通過的項目修正後再驗，不將 Chromium 測試結果當作實機完成。

若要回復已啟用 PWA 的版本，請由工程師提供保留相容 Service Worker 的更新／停用方案。不要單純發布沒有 `sw.js` 的早期產物，也不要叫使用者清空網站資料來回退，否則舊快取可能持續控制頁面或私人內容遺失。

在兩支 iPhone、同一個**專用測試帳本**驗證以下項目，不修改真實旅費來假裝完成：

- 手機甲新增、乙看到；乙修改、甲看到；刪除後一致；關閉重開仍保留。切換前景、斷線重連都取得最新資料。
- 同時新增不同消費保留兩筆；同筆保留舊表單後由另一手機先修改，舊表單送出被拒絕並提示衝突；連點／失敗重送不重複入帳。
- 兩位均付款；奇數平均額外 1 圓由付款人負擔，單人與自訂總和正確。修改／刪除後、共同匯率、部分／完整結算與 CSV 金額一致。
- 第三個無私人連結的匿名裝置／未驗證請求不能讀寫原帳本；改請求帳本 ID 無法越權，直接寫表不能繞過 RPC；新連結輪替撤銷舊裝置。這些安全項目需對正式專案實際驗證，表存在／RLS 開啟本身不等於驗收通過。

## 環境限制

2026/11/09 此雲端可執行建置和 Chromium 測試，但目前生效的網路規則仍未允許 `api.github.com`、Supabase 專案、Open-Meteo 與 Pages 網址，GitHub API 新連線取得 CONNECT 403。這不代表手機網路或 Supabase 金鑰錯誤。未完成自動建立 PR、正式雲端完整測試與真實站點驗證，不能據此假裝已完成；Git 原始碼分支可另行推送備份。
